## Changelog Archive - 2026


### v9.7.0 - 13th September 2026

- Added `eval/style_rhythm.py`, promoted from a chat agent's script:
  - `split_conversations()`: splits a report's replies back into conversations.
  - `turn_matrix()`: one 0/1 row per conversation, one column per turn a rule applied to.
  - `decompose_rhythm()`: splits the violations into position drift, conversation spread and within-conversation momentum.
  - `RhythmDecomposition`: the result, with `summary()`.
  - `MIN_RHYTHM_CONVERSATIONS`, `MIN_RHYTHM_TURNS`, `RHYTHM_TRIALS`.
- Added 19 unit tests in `tests/test_style_rhythm.py`.
- Updated `README.md`: "Where inside a conversation a rule breaks".


### v9.6.0 - 13th September 2026

- Added in `eval/style_history.py`:
  - `Verdict.RARE`: a rule its prior invocations broke less than once each on average is shown and never judged, so it is never in `worse` or `better`.
  - `RARE_VIOLATIONS_PER_INVOCATION`: that threshold, also exported from `agents7.eval`.
- Updated `HistoryComparison.summary()`: marks rare rules `rare` and explains the mark.
- Added unit tests in `tests/test_style_history.py`:
  - 5 tests for the rare verdict.
  - Updated `test_agreeing_priors_still_buy_no_more_than_half_an_event` for it.
- Updated `README.md`: documents the rare verdict and the jump it does not catch.
- Updated `.claude/rules/measurement-needs-history.md`: rule 4 says rare rules are reported, not judged.


### v9.5.0 - 13th September 2026

- Updated `eval/style.py`:
  - Added `repeats_opener()`: a conversation's first message is a violation when another conversation in the same invocation opened with the same line. Declarable by name in YAML.
  - Updated `_score`: a check whose callable carries `bind_runs(runs)` is given every run before it scores one, so a check can compare conversations with each other.
- Added 6 tests in `tests/test_style_contract.py`.
- Updated `README.md`: `repeats_opener` and the `bind_runs` hook.


### v9.4.0 - 13th September 2026

- Updated `eval/style_history.py`:
  - Added `RuleRecord.by_script`: the runs added up per script, in the order scripts ran.
  - Added `RuleComparison.by_script` and `RuleComparison.script_split`: the invocation's rate per script, for reading only; the verdict stays on the pooled rate.
  - Updated `HistoryComparison.summary()`: prints an indented per-script line under a rule when two or more scripts exercised it and at least one reply broke it.
- Added 5 tests in `tests/test_style_history.py`.
- Updated `README.md`: sample comparison output shows the split.


### v9.3.0 - 13th September 2026

- Added `StyleRunRecord.guard_answered_by` in `eval/style_history.py`:
  the models the provider says answered the guard's calls, read by
  `record_style_run` from the run. `guard_model_id` keeps the
  configured name, which is what it always held; its docstring now
  says so.
- Updated `compare_to_history`: a band only holds invocations whose
  guard was answered by the same model, checked separately from
  `answered_by`, and the summary names the guard model of any
  invocation left out. The fingerprint is unchanged, so no stored
  key moves.
- Updated `README.md`: the guard's answering model.
- Updated `.claude/rules/metrics-completeness.md`: instance 19.
- Added 6 tests in `tests/test_style_history.py`.


### v9.2.0 - 13th September 2026

- Added `banned_fact_phrases` in `agents/chatter.py`:
  - `Chatter.banned_fact_phrases`: phrases no character fact may
    carry. `remember()` does not store a fact containing one, and
    a stored fact containing one is left out of the prompt with a
    warning naming it. The fact file is not edited. Matching
    ignores case and spacing; a blank phrase is rejected.
- Updated `agents/config_loader.py`: `character_facts.banned_phrases`
  in YAML sets it.
- Updated `README.md`: documented the option and why a stored fact
  needs it.
- Added 8 tests in `tests/test_character_facts.py`.

### v9.1.0 - 13th September 2026

- `eval/`:
  - Added `copies_example` in `style.py`: a message counts as a
    copy of an example line when it contains the line or scores at
    least `min_similarity` (default 0.7) against it. Lines and
    messages under `min_chars` (default 16) are skipped.
  - Updated `style.py`:
    - Added `StyleRule.definition`: a hash of the check's name and
      arguments, set by `build_rule`. `None` for a rule built around
      a bare callable.
  - Updated `style_history.py`: each rule keeps its own history:
    - Added `configuration_key`: `fingerprint_run` without the rule
      ids. `fingerprint_run` itself is unchanged.
    - Added `RuleRecord.definition` and `StyleRunRecord.config_key`,
      both filled by `record_style_run`.
    - Updated `compare_to_history`: records that both carry a
      `config_key` are matched on it, so adding a rule leaves the
      other rules' bands in place. A rule's band only takes runs with
      the same definition. Records without the fields compare as
      before.
  - Updated `__init__.py`: exports `configuration_key`.
- Added tests:
  - `tests/test_style_contract.py`: 8 tests.
  - `tests/test_style_history.py`: 9 tests.
- Updated `README.md`: `copies_example`, and per-rule history in
  "Comparing runs over time".
- Updated `.claude/rules/measurement-needs-history.md`: rule 2, the
  rule set is identity for the record, not for the band.


### v9.0.2 - 13th September 2026

- Fixed: a chat call that raised left no record in the call log, so
  a run could lose conversations to `Connection error.` while its log
  showed no failed call.
  - `agents/chatter.py`: added `Chatter._log_failed_call`, which
    writes a `CallRecord` with `success=False`, the error, the
    messages sent, and how long the call waited before failing.
    Tokens are zero because nothing came back; the cost is left
    `None` rather than written as zero. `_log_call` gained an
    `error` field.
  - `agents/chatter.py`: the plain and async replies, both ways of
    opening a stream, and a stream that breaks part way (through
    the new `_chunks` / `_achunks` iterators) now log their
    failure before re-raising.
  - `agents/guarded.py`: guarded generation and the guard's own
    check do the same, the guard's failure recorded under the
    guard's name, version and model.
- Fixed: a call that never succeeded lost its retry count.
  - `llm/retry.py`: added `attach_attempt_stats`, which puts the
    loop's `retries` and `retry_duration` on the exception that
    ends a call, every failed attempt counted, the last included.
  - `llm/dispatcher.py`: attaches them wherever a failure leaves
    the dispatcher — no fallback, a failed fallback, and the async
    timeout — so a failed record reports what the call cost in
    time.
- Added 9 tests: 7 in `tests/test_call_log.py`, 2 in
  `tests/test_dispatcher.py`.
- Updated `.claude/rules/metrics-completeness.md`: instance 18.


### v9.0.1 - 13th September 2026

- Fixed `agents/persona.py`: `Scene.to_summary()` now includes the
  scene's `goal`, so the guard knows what the character is there to
  do. The character's own prompt always had it; the guard's never
  did. Without the goal, the guard could reject the scene's own goal
  as off-topic.
  - Changes the guard prompt of every guarded scene agent with a
    goal (the `guarded_scene_david` and
    `thomas_scene` samples). The guard's prompt is part of
    `fingerprint_run`, so guarded style histories start a fresh
    baseline; unguarded ones are unaffected.
- Added 4 tests in `tests/test_guarded_scene.py`: the goal reaches
  `to_summary()`, the YAML loader's summary, and a Python-built
  guard, and a scene without a goal adds no `Goal:` line.


### v9.0.0 - 13th September 2026

- Updated `eval/style_history.py`: a baseline now only holds
  invocations answered by the same model:
  - Added `StyleRunRecord.answered_by`: the models the provider
    reported for the agent's own calls (`CallRecord.model`), sorted.
    Empty when no call reported one, and on every older record.

    name the resolved one.
  - Updated the `fingerprint_run` docstring: the chatter's model
    stays out of the hash, and the split happens in the comparison.
- Added 8 tests in `tests/test_style_history.py`.
- Updated `README.md`: the "Comparing runs over time" section.
- Updated `.claude/rules/`:
  - `metrics-completeness.md`: instance 17, the style history
    recording the configured model.
  - `measurement-needs-history.md`: rule 8 names the answering
    model, and asks for a same-day control of the unchanged config
    before a move is credited to an edit.

### v8.5.0 - 6th September 2026

- Added character / chat-goal composition to the YAML config loader:
  - `agents/config_loader.py`:
    - `character` and `chat_goal` each name a YAML file, folded into
      the config: the character file holds `persona`, the chat-goal
      file holds `scene`. Either axis can be swapped without
      touching the other.
    - Neither fragment may hold the other's section, nest another
      fragment, or declare `base_config` — the split is enforced
      rather than suggested, so a config that has been split cannot
      quietly grow back into one file.
    - `extra_instructions` and `opening_instructions` accumulate
      across the composition — character, then chat goal, then the
      agent config — instead of one silently replacing another.
      Every other key is a deep merge with the agent config winning.
    - `resolve_config()`: the resolved configuration as a mapping,
      for anything that reads a config rather than building the
      agent.
- Added the `$character` placeholder:
  - `agents/chatter.py`: a persona-driven chatter resolves
    `$character` to the persona's `full_name` without being asked,
    so a chat-goal file can write a worked example without naming
    who is in it. An explicit `prompt_params` or `context_params`
    entry of that name still wins.
  - `agents/base.py`: `BaseAgent.substitute()` applies the agent's
    placeholder mapping to any text. `resolved_system_prompt` is now
    one call to it, and the chatter uses it for
    `opening_instructions` and `opening_prompt`, which join the
    prompt per call rather than being part of it.
  - `agents/guarded_scene.py`: the guard's scene summary is
    substituted before it reaches the guard, which is its own agent
    with no persona and could not resolve the placeholder itself.
- Added unit tests:
  - `tests/test_config_composition.py`: 23 tests.
  - `tests/test_chatter.py`: 6 tests for the placeholder.

### v8.4.0 - 6th September 2026

- Updated `eval/chat_review.py`: the report is split into tabs —
  Verdicts, Numbers, one per conversation, and Findings. Read as one
  scroll, the conversations were buried under the apparatus:

    `#242b37` and every surface, line and wash with it.
  - **The dark palette is now written once**, as `_DARK`, and both
    dark blocks are generated from it. CSS cannot share a declaration
    block between a media-conditional selector and a plain one, so
    the page needs the same tokens twice; keeping two hand-written
    copies in step failed twice in one afternoon, and the second
    failure shipped white bubbles with invisible text to everyone
    whose system is dark.
  - Added the tab bar's rules.
- Updated `tests/test_chat_review.py`: the dark blocks are checked
  against `_DARK` as well as against each other.


### v8.3.0 - 6th September 2026

- Updated `eval/_review_theme.py`: reworked the review page's palette.
  Colour now means exactly one thing on the page — what kind of
  finding a note is:
  - Structure is ink and slate. The rule above the title, the
    caveat's edge, the pressed toggle and focus rings took a warm
    amber that fought the cool ground; they are now the text colour.
  - The two speakers are told apart by depth rather than hue. The
    agent's bubble sits on its own surface with an edge and a shadow,
    the counterpart's is recessed. `--bubble-agent` and
    `--bubble-other` keep the agent the lighter of the two in both
    themes, which `--surface` could not.
  - A note's prose is now the page's text colour, with only its label
    and left edge carrying the kind. A paragraph set in red is harder
    to read than one in ink, and a column of them read as a warning
    sign rather than as findings.
  - Fixed the pressed toggle setting `color: #fff` and then
    overriding itself with a hardcoded dark brown one rule later.
- Added `Read.read_id` and the spec's `read_id` key: a read is
  excluded from its own history when the comparison column is built.
  Without it, re-rendering a page after recording its figures
  compared the read against itself and every row showed no change.
- Updated `write_review()`: a read already in the history file is
  left alone rather than filed a second time, so re-rendering after
  rewording a note is safe.
- Added theme guards to `tests/test_chat_review.py`: every variable
  the light palette declares must ship a dark value in both dark
  blocks, the two dark blocks must agree, and no rule may hardcode a
  colour. The missing-token bug this catches had shipped in the same
  change that introduced it.


### v8.2.0 - 6th September 2026

- Added `eval/chat_review.py`, the second instrument for chat agents:
  the human read, where `style.py` is the mechanical one. Recording
  and rendering are separate, so a conversation is paid for once and
  can appear on any number of later pages:
  - `ConversationRecorder`: drives one conversation a turn at a time,
    attaching the guard callback itself, and rewrites its file after
    every turn. Nothing it captures can be reconstructed afterwards.
  - `Recording`, `TurnRecord`, `GuardAttempt`: the saved conversation,
    carrying every timing, token count, cost and guard verdict, plus
    the model each call actually named. `save_recording()` and
    `load_recording()` move them.
  - `load_read()`: builds a read from a YAML spec naming which
    recordings to show and what the reader made of each turn. The
    recordings may be any age and any version.
  - `render_review()`, `write_review()`: the review page, with the
    Read/Review toggle, the four note kinds, the per-turn split of
    agent against guard time and cost, and the guard's own attempts.
    Makes no LLM calls.
  - `ReadRecord`, `append_read()`, `load_read_history()`,
    `measure_read()`: an append-only history, so a read's comparison
    column fills itself from the one before it.
- Added `eval/_review_theme.py`: the page's stylesheet, so every read
  of every chat agent renders as the same document.
- Added `agents7 chat-review`: renders a read's spec to an HTML file,
  optionally appending its figures to a history.
- Added `tests/test_chat_review.py`: 55 tests.
- Updated `.claude/rules/chat-agent-validation.md`: the review page is
  generated rather than designed. Four reads had produced four
  different-looking pages because the rule described what a page must
  contain and never what it looks like.


### v8.1.0 - 5th September 2026

- Added `eval/style_arms.py`, promoted from a chat agent's script:
  - `compare_arms()`: reads two sets of style-contract invocations
    against each other on the mean rate, the spread between whole
    invocations, and the spread between individual conversations.
    `compare_to_history` judges one configuration against its own
    past; this answers whether two configurations wobble by
    different amounts, which a band cannot express.
  - `ArmComparison`, `RuleArms`, `DriftRow`: the typed result, with
    `summary()` rendering the three tables and the panel.
  - Significance is by exact permutation of whole invocations,
    never of conversations — two conversations inside one
    invocation are not exchangeable with two inside another.
  - Every p-value carries the size of difference the test could
    have seen (`RuleArms.spread_threshold`,
    `ArmComparison.panel_threshold`); rules that never fire are
    excluded from the panel; and binomial noise is subtracted
    before conversation spreads are compared, so a difference in
    level cannot read as a difference in wobble.
  - `trim` reports what it held back as `drift_left` /
    `drift_right` instead of dropping it silently, and now trims
    whichever arm is longer rather than assuming it is the right.
- Added `tests/test_style_arms.py`: 24 tests.
- Updated `README.md`: documented `compare_arms` under the
  style-contract section.


### v8.0.1 - 5th September 2026

- Fixed `eval/style.py`:
  - `StyleReport.summary()`: a budget below 1% printed as `<=0%`,
    which is what a rule tolerating nothing prints. Two thresholds
    a whole event's worth apart read as the same number, so a
    reader could not tell which one a run had cleared. Whole
    percents still print whole; a fractional one keeps its decimal.


### v8.0.0 - 5th September 2026

- Updated `eval/style_history.py`:
  - `fingerprint_run()`: a rule's `budget` is no longer part of the
    hash. It is read once, in `RuleResult.passed`, against a rate
    that has already been measured, so it cannot move a number —
    and keying on it meant that writing down the thresholds a
    baseline had just justified discarded that baseline. The one
    edit guaranteed to leave every measurement untouched was also
    guaranteed to reset every band. Adding or removing a rule still
    changes the hash, because the rule ids do.
- **Every stored fingerprint changes.** A history file written by
  an earlier version stops matching runs made by this one, and the
  comparison reports `Verdict.NO_BASELINE` rather than a wrong
  answer. Records whose configuration can still be rebuilt should
  be re-filed under their new keys; see the exception in
  `.claude/rules/measurement-needs-history.md` for the four
  conditions that permits.
